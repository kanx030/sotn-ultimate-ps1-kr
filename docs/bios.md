# 바이오스별 실행 확인 (2026-11-13)

"아무 바이오스로나 한글 패치판이 돌아가는가?"를 확인하려고, RetroArch 코어 세 개(SwanStation = DuckStation 코어, PCSX-ReARMed, Beetle PSX = mednafen_psx)에서 바이오스를 하나씩 바꿔 가며 처음부터 켜 봤습니다.

## 결론
- **우리 패치 탓으로 안 되는 경우는 하나도 없었습니다.** 실패한 조합은 모두 원본 v1.4도, 심지어 개조하지 않은 북미판 `Castlevania - Symphony of the Night (USA)`도 똑같이 실패합니다. 그래서 빌드 도구는 고치지 않았고 rel14d도 만들지 않았습니다.
- 북미 바이오스(v2.2·v3.0·v4.1·v4.5)는 세 코어 모두 정상. 유럽 v2.2(DTL-H3002)·v4.1(SCPH-7502), 일본 v2.2(SCPH-5000)도 정상.
- 바이오스 없이(내장·대체 바이오스)도 세 코어 모두 프롤로그 대사까지 정상: PCSX-ReARMed HLE, SwanStation 내장 OpenBIOS, Beetle PSX 내장 대체 바이오스.
- **안 되는 것:** 일본 v3.0(SCPH-5500)·v4.0(SCPH-7000)은 북미 디스크를 거부하고 바이오스 메뉴 화면(메모리 카드/CD 플레이어)으로 감. 북미 정품 SOTN도 똑같음 → 바이오스·지역 문제.
- 사용자 폴더의 `SCPH5000.BIN`, `Scph5502.bin`은 표준 덤프와 MD5가 다름(아래). 이 두 파일은 코어에 따라 검은 화면·에뮬레이터 종료가 나고 원본도 같음 → 바이오스 파일 문제.

## 시험 방법
- 이미지: 우리 `work/build/bt14.bin`(rel14b와 같은 소스, `--test`로 RAM 패드 입력 훅만 추가), 배포 `rel14b.bin`, 원본 `SOTN Ultimate (PS1 Version) v1.4.bin`, 북미 정품 SOTN.
- 우리 이미지는 켜기 → 제목 → 메인 메뉴 → 파일 선택 → 새 게임 → 이름 → 알카드·설정 → 오프닝(빨리 감기) → 프롤로그 → 드라큘라 앞 첫 대사 두 쪽까지. 게임 상태(0x8003C734: 1 제목, 8 메뉴, 5 오프닝, 2 게임)를 읽어 단계마다 확인하고 갈무리.
- 원본·정품·배포판은 입력 훅이 없어 켜서 제목이 뜨는지만 75초 지켜봄.
- 도구: `tools/biostest.py` (코어·바이오스·이미지 하나씩, 새 RetroArch 창, 포트 55367, 자기 PID만 종료, 바이오스는 임시 폴더에 복사했다가 끝나면 지움). 결과·갈무리·기록: `test/bios_test/` (깃 제외).
- RetroArch 설정은 `test/ra3.cfg` 복사본. **사용자 RetroArch의 코어별 덮어쓰기 설정(`config/Beetle PSX/Beetle PSX.cfg`, `config/PCSX-ReARMed/PCSX-ReARMed.cfg`)이 시스템 폴더를 바꿔 버려서** 처음 한 바퀴는 PCSX가 전부 HLE, Beetle은 내장 대체 바이오스로 돌았음 → 덮어쓰기를 끄고(`auto_overrides_enable=false`) 다시 돌린 결과만 아래에 적음. 실제로 바이오스가 쓰였는지는 코어 기록(PCSX "Loaded BIOS", SwanStation "Using BIOS")과 커널 영역 메모리 비교(Beetle)로 확인.
- SwanStation은 바이오스 지역에 맞춰 콘솔 지역을 고름(일본 바이오스 → NTSC-J, 유럽 → PAL). PCSX·Beetle은 디스크 지역(북미) 그대로.

덧붙임
- SwanStation에서 일본 바이오스를 북미 콘솔 지역(자동)에 끼워도 결과는 같음: v2.2 일본은 정상(표의 SCPH-5000 결과가 이 조건), v3.0·v4.0 일본은 메뉴. 원본 v1.4도 북미 콘솔 지역 + SCPH-5500에서 메뉴.
- 예전 DuckStation 확인(`docs/duckstation.md`)에서 SCPH-5500으로 돌았던 것은 최신 DuckStation 데스크톱판(0.1-12640) 결과. 같은 계열이지만 오래된 SwanStation에서는 그때 쓴 `test/system/scph5500.bin`(표준과 다른 덤프)으로도, 콘솔 지역 NTSC-J·자동 모두 메뉴로 감. 일본 v3.0 이후 바이오스로 북미 디스크가 도는지는 에뮬레이터 판에 달린 문제.
- 처음 한 바퀴에서 SwanStation SCPH-7003·SCPH-7502가 이름 입력·대사에서 멈춘 것은 입력 타이밍 문제(자동 조작이 화면 전환보다 빨랐음)였고, 화면 전환을 기다리게 고친 뒤 다시 돌려 둘 다 정상.
- 정품 북미 SOTN 대조: SCPH-1001은 세 코어 모두 제목까지 정상, SCPH-5500·7000은 세 코어 모두 메뉴.

## 우리 시작 코드와 바이오스
- 우리 패치는 실행 파일 시작 주소를 시작 코드(0x80043000)로 바꾸고, 글꼴·치트 덩어리(실행 파일 안 0x80033BE8~)를 0x801F0000~0x801FF000으로 복사한 뒤 원래 시작점(0x80010DFC)으로 뜀. 실행 파일 머리의 BSS 크기는 0이라 바이오스가 실행 전에 지우는 영역이 없음. 스택(0x801FFF00/0x801FFFF0)은 복사 범위 위.
- HLE(PCSX)·OpenBIOS(SwanStation)·Beetle 내장 대체 바이오스 모두 커널을 0x80000000~0x8000FFFF에 두므로 겹치지 않음. 실제로 세 대체 바이오스 모두 메뉴·대사 글꼴까지 정상.
- 실패한 조합은 모두 게임 실행 파일이 시작되기 전(바이오스 단계)에 멈춤: 게임 상태 값이 한 번도 0이 되지 않음. 우리 시작 코드까지 가지도 않으므로 패치로 고칠 수 있는 부분이 아님.

## 사용자 안내
1. 북미 바이오스(SCPH-1001, 7001, 7003, 101 등) 권장. 유럽 v4.1(SCPH-7502)·v2.2, 일본 v2.2(SCPH-5000 정품 덤프)도 됨.
2. **일본 SCPH-5500·SCPH-7000(및 그 이후 일본 바이오스)은 북미 디스크를 거부**함. 바이오스 메뉴(메모리 카드/CD 플레이어)가 뜨면 북미 바이오스로 바꿀 것. 원본 Ultimate와 정품 북미판도 같음.
3. 바이오스 파일이 표준 덤프인지 MD5로 확인 (SCPH-1001: `924e392ed05558ffdb115408c263dccf`).
4. 바이오스가 없어도 PCSX-ReARMed(HLE), SwanStation·Beetle(내장 대체 바이오스)로 프롤로그까지 돌아가지만, 원작자는 실제 바이오스를 권장하고 이 확인은 게임 앞부분까지만이므로 실제 바이오스를 쓰는 편이 안전.
5. RetroArch에서 코어별·게임별 덮어쓰기 설정이 시스템 폴더를 바꾸면 의도와 다른 바이오스(또는 HLE)가 쓰일 수 있음. 코어 기록이나 화면의 바이오스 이름으로 확인.
